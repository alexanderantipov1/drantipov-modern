# AI/LLM Authority Knowledge Pages Blueprint

A reusable framework for creating 50+ SEO pages optimized for AI citation, LLM search visibility, and organic search. Originally developed for a dental implant practice; adaptable to any industry.

---

## Purpose

These pages are designed to:
- Rank for long-tail informational queries (e.g., "how much does [service] cost")
- Get cited by AI assistants (ChatGPT, Perplexity, Google AI Overviews)
- Build topical authority through pillar/cluster content architecture
- Generate leads through embedded CTAs and internal linking

---

## Architecture Overview

### Data-Driven Template System

All pages share ONE reusable template component. Each page is just a data object passed to the template. This means:
- Consistent layout, schema markup, and CTA placement across all pages
- Content authors only write data — no code needed
- Easy to add 10 or 100 pages with zero development work

### Pillar/Cluster Model

Pages are organized into **pillars** (broad topics) with **clusters** (specific sub-topics):

```
Pillar: [Main Service]
├── /[main-service]/cost
├── /[main-service]/procedure
├── /[main-service]/recovery
├── /[main-service]/risks
├── /[main-service]/candidates
└── /[main-service]/maintenance
```

Each pillar has a **hub page** that links to all its clusters, and each cluster links back to the hub and to related clusters.

---

## Page Data Structure

Every knowledge page is defined by this data shape:

```typescript
interface KnowledgePage {
  // SEO & Routing
  title: string              // H1 heading + SEO title (keep under 60 chars)
  slug: string               // URL path (e.g., "/main-service/cost")
  pillar: string             // Category for breadcrumbs and grouping
  metaDescription: string    // Meta description (under 160 chars)
  keywords: string[]         // Target keywords for internal tracking

  // Content
  introText: string          // Hero section subtitle (2-3 sentences, include key stats)
  sections: ContentSection[] // Main body content (3-5 sections per page)
  faqs: FAQ[]                // 3-5 FAQs with concise answers
  relatedLinks: Link[]       // 3-4 links to related pages (internal linking)
}

interface ContentSection {
  heading: string            // H2 heading
  content: string            // HTML string (paragraphs, lists, tables, h3 subheadings)
}

interface FAQ {
  question: string           // Written as a natural question someone would ask
  answer: string             // Direct answer in 2-3 sentences
}

interface Link {
  label: string              // Anchor text
  href: string               // Internal URL
}
```

## Template Component Features

The shared template automatically provides:

1. **JSON-LD Structured Data**
   - FAQPage schema (from FAQ array)
   - MedicalWebPage / Service schema (from title + description)
   - Organization/Business schema (from site config)

2. **Layout**
   - Gradient hero with title, breadcrumbs, and intro text
   - Content sections with H2/H3 hierarchy
   - "Why Choose [Business]" CTA card with USPs
   - FAQ accordion
   - Related pages grid
   - Booking CTA footer

3. **SEO**
   - Proper heading hierarchy (H1 > H2 > H3)
   - Internal linking via relatedLinks
   - English-only hreflang (no translated versions)
   - Included in sitemap with proper priority

## Content Writing Guidelines

### Intro Text
- Lead with a clear, factual answer (price, timeline, success rate)
- Include your key differentiator or USP
- 2-3 sentences max
- Example: "[Service] costs range from $X to $Y. At [Business], our [USP] allows us to offer [benefit] — backed by [guarantee]."

### Content Sections (3-5 per page)
- Each section = one H2 heading + HTML content
- Use H3 subheadings within sections for sub-topics
- Use bullet lists for features, benefits, and comparisons
- Use tables for side-by-side comparisons (especially for vs-pages)
- Keep paragraphs to 2-3 sentences max
- Use plain language (aim for 8th-grade reading level)
- Include specific numbers: prices, timelines, percentages, stats
- Mention your business name 2-3 times naturally per page

### FAQs (3-5 per page)
- Write questions as real people would ask them (conversational tone)
- Start answers with a direct response, then add detail
- Keep answers to 2-3 sentences
- Target "People Also Ask" queries from Google
- These generate FAQPage schema automatically

### Related Links (3-4 per page)
- Link to pages in the same pillar and adjacent pillars
- Use descriptive anchor text (not "click here")
- Create a web of internal links across all pages

### Comparison Pages (vs-pages)
- Always include a side-by-side comparison table
- Be factual and specific — cite numbers, not opinions
- Address the exact query someone would search
- Include a "which is right for you" section

### For each page:
- [ ] Title under 60 characters
- [ ] Meta description under 160 characters
- [ ] 3-5 target keywords defined
- [ ] 3-5 content sections with H2 headings

### Site-wide:
- [ ] Hub pages for each pillar linking to all cluster pages
- [ ] Dynamic [slug] routes for pillar sub-pages
- [ ] Sitemap includes all pages with proper priority
- [ ] English-only hreflang (no translated versions for knowledge pages)

- [ ] llms.txt file with business summary and key facts
- [ ] AI Plugin Manifest at /.well-known/ai-plugin.json
- [ ] robots.txt explicitly allows: GPTBot, ChatGPT-User, ClaudeBot, PerplexityBot, Google-Extended
- [ ] Structured data on every page for programmatic AI access
- [ ] FAQ answers written as direct, citable statements

## Implementation Steps (for a new industry)

### Step 1: Define Your Pillars (30 min)
Identify 4-6 broad topic categories. Example for a law firm:
- Personal Injury
- Car Accidents
- Workers' Comp
- Slip and Fall
- Medical Malpractice
- Comparisons (us vs competitor, service vs alternative)

### Step 2: Map Cluster Topics (1 hour)
For each pillar, create 4-8 sub-topics using these universal patterns:
- Cost / pricing
- Process / procedure / how it works
- Timeline / how long it takes
- Recovery / what to expect after
- Risks / complications / what can go wrong
- Candidacy / eligibility / am I a good fit
- Results / success rate / outcomes
- Maintenance / long-term care

### Step 3: Write Content Data (2-3 days)
For each page, fill in:
- title, slug, pillar, metaDescription, keywords
- introText (2-3 sentences with key fact)
- 3-5 sections (H2 heading + HTML content with lists/tables)
- 3-5 FAQs
- 3-4 relatedLinks

### Step 4: Build Template + Routing (1 day)
- Create the shared template component
- Set up dynamic [slug] routes for each pillar
- Wire up the data → template rendering
- Add JSON-LD schema generation

### Step 5: Configure SEO (2 hours)
- Add pages to sitemap config
- Set up hreflang (English-only for knowledge pages)
- Create llms.txt and AI plugin manifest
- Verify robots.txt allows AI crawlers
