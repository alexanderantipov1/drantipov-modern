Footer Framework and Strategy
A reusable guide to rebuilding the Fusion Dental Implants footer on another website. It contains two things:

The framework - the actual code and how it is structured.
The strategy - why each section and link is in the footer, so you can apply the same thinking to a different site.
This is built for a Next.js (App Router) site using React, TypeScript, and Tailwind CSS. If your other site uses the same stack, you can paste the code almost as-is. If it uses a different stack, follow the structure and the reasoning, and swap the syntax.

Part 1: The Framework (How It Is Built)
The core idea: split the footer into two files
The footer is intentionally split into two pieces:

A server component that fetches the translated text and the current language, then passes them down.
A presentational component that renders the visible footer using that data.
Why split it this way:

Translations are resolved on the server, so the browser does not do extra work to figure out language. This keeps the footer fast.
The visible footer stays lightweight and easy to edit.
It avoids a common multi-language "hydration mismatch" bug, where the server and browser render different text and React complains.
If your other site is single-language, you can skip the server file entirely and hard-code the labels in the presentational component.

Key design decisions (the framework rules)
Link lists are plain data, separated from layout. Every footer section is defined as a simple array of { href, label } near the top of the file. Adding or removing a link is a one-line change. The rendering code never changes.

Accordions use native HTML, not JavaScript. Each collapsible section is a native <details>/<summary> element. This means the footer expands and collapses even before any JavaScript loads, it is accessible by default, and it adds zero JavaScript weight. The only "interactive" styling is a chevron that rotates via CSS when the section is open.

Every link is language-aware. Links pass through a single helper (localizeHref) that decides whether to add a language prefix (like /es/). Pages that exist in every language get the prefix; pages that only exist in one language are left unprefixed so visitors are not sent to a missing translated page.

The brand block is always visible; the rest collapses. The top block (name, description, phone, email, address, social, main call-to-action) is always shown. The seven link sections are collapsed by default so the footer stays compact, especially on mobile.

The year is automatic. The copyright year is generated at render time, so it never needs manual updating.

File 1: The server component (translations)
// FooterWithI18n.tsx
import { getI18n, getCurrentLocale } from "@/locales/server";
import { Footer } from "./Footer";
// Only the keys the footer actually needs - keep this list small.
const FOOTER_KEYS = [
  "navigation.footer.about",
  "navigation.footer.aboutDescription",
  "navigation.footer.aboutUs",
  "navigation.footer.allRightsReserved",
  "navigation.footer.blog",
  "navigation.footer.company",
  "navigation.footer.contact",
  "navigation.footer.forDentists",
  "navigation.footer.hipaaNotice",
  "navigation.footer.privacyPolicy",
  "navigation.footer.services",
  "navigation.footer.termsOfService",
  "navigation.footer.yourJourney",
  "navigation.header.scrollToTop",
] as const;
export async function FooterWithI18n() {
  const t = await getI18n();
  const currentLocale = await getCurrentLocale();
  const translations: Record<string, string> = {};
  for (const key of FOOTER_KEYS) {
    translations[key] = t(key as never);
  }
  return <Footer translations={translations} currentLocale={currentLocale} />;
}

// ---- Reusable collapsible section ----
function AccordionSection({
  title,
  links,
  localizedHref,
  defaultOpen = false,
}: {
  title: string;
  links: LinkItem[];
  localizedHref: (href: string) => string;
  defaultOpen?: boolean;
}) {
  return (
    <details className="group border-b border-white/10" {...(defaultOpen ? { open: true } : {})}>
      <summary className="flex items-center justify-between py-4 cursor-pointer list-none [&::-webkit-details-marker]:hidden">
        <h3 className="text-base font-bold text-white">{title}</h3>
        <ChevronDown className="h-5 w-5 text-blue-200 transition-transform duration-200 group-open:rotate-180" />
      </summary>
      <ul className="pb-4 space-y-2 text-sm text-blue-100">
        {links.map((link) => (
          <li key={link.href}>
            <Link href={localizedHref(link.href)} className="hover:text-white transition-colors">
              {link.label}
            </Link>
          </li>
        ))}
      </ul>
    </details>
  );
}

If your other site is single-language
Delete the server file and the translation plumbing. In Footer.tsx, remove the translations and currentLocale props, replace every t("...") call with the plain text, and replace localizedHref(href) with just href. Everything else stays the same.

Part 2: The Strategy (Why Each Item Is in the Footer)
A footer is not a junk drawer. It is doing three jobs at once: helping people find things, helping search engines understand and crawl the whole site, and giving one more chance to convert a visitor into a booking. Each section below is chosen for one or more of those jobs.

The guiding principles
The footer is the site's safety net for navigation. When a visitor scrolls to the bottom, they did not find what they wanted in the main content. The footer should answer "where do I go next?" without making them hunt.

The footer spreads internal links for SEO. Search engines follow links to discover and rank pages. Because the footer appears on every page, links placed here pass "link equity" sitewide and help important pages get crawled and ranked. This is why money pages, location pages, and key comparisons all appear here.

The footer is a final conversion point. Phone, email, address, and a bright "book now" button are always visible so a ready-to-act visitor never has to scroll back up.

Group by how the visitor thinks, not by how the company is organized. People search by service ("All-on-4"), by place ("dentist near Roseville"), by money ("how much does it cost"), and by trust ("are these people legit"). The sections map to those mindsets.

Show a little, hide the rest. The footer holds a lot of links for SEO, but showing them all would overwhelm. Collapsing them keeps it clean while keeping every link in the page's HTML for search engines.

Why each section exists
Brand block (name, description, phone, email, address, social, main button)

Establishes who you are and that you are a real, contactable business. The physical address and phone are also local-SEO signals (they should match your Google Business Profile exactly).
The social icons build trust and give an exit to active, proof-filled profiles.
The orange "Schedule Free Consultation" button is the single most important action on the site, repeated at the bottom of every page.
Services

These are the money pages, the actual treatments people pay for. They get top billing because they are both the most valuable to the business and the most likely to rank and convert.
Notice it goes from broad ("Dental Implants Overview") to specific ("All-on-4", "Full Mouth", "Same-Day"). This mirrors how a patient narrows down their research, and it gives search engines a clear topic structure.
Cities We Serve

This is pure local SEO. Each city link targets people searching "dental implants + [their town]." A dedicated page per city can rank for that town's searches, and the footer makes sure all of them are linked from every page.
It ends with a "View All Locations" link so the footer does not have to list every single place.
General Dentistry

Captures visitors who came for implants but also need (or have family who need) routine care. It widens the net and signals to search engines that the practice covers a full range of services, not just one.
Costs & Financing

Cost is the number one question and the number one objection in implant dentistry. Surfacing pricing, a calculator, and financing options directly answers the visitor's biggest worry and builds trust through transparency. It also captures high-intent searches like "dental implant cost" and "implant financing."
Resources & Education

Blog, galleries, and comparison guides ("Implants vs. Dentures", "All-on-4 vs. All-on-6") serve people who are still researching and not ready to buy. This content earns search traffic, answers questions, and nurtures undecided visitors toward a decision.
Before-and-after galleries and case content also act as social proof.
Company

About, providers, and contact build trust. In healthcare especially, people want to know who is treating them and what their credentials are. "For Dentists" and "Referral Partners" serve a separate audience: other professionals who send referrals.
Legal

Privacy Policy, Terms, and (for a medical site) HIPAA Notice. These are required for compliance and credibility. They live in their own small section and are repeated in the bottom bar so they are always one click away.
Bottom bar (copyright + legal links)

The minimum every footer needs: who owns the site, the year, and quick legal links. Kept visually separate and quiet so it does not compete with the navigation above.
How to adapt this to a different business
Keep the framework and the job each section does; swap the content to fit your site:

Services -> your core products or services, ordered broad to specific.
Cities We Serve -> keep only if you serve specific geographic areas. If you are online-only, replace with a "Use Cases" or "Industries" section.
Costs & Financing -> whatever your biggest customer objection is (pricing, shipping, returns, security). Address it head-on here.
Resources & Education -> your blog, guides, help center, or docs.
Company -> about, team, careers, contact.
Legal -> privacy and terms at minimum; add industry-specific notices as needed.
The rule to carry over: every link in the footer should earn its place by doing at least one of the three jobs (help navigation, help SEO, or help conversion). If a link does none of those, leave it out.
